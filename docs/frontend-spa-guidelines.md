# Frontend SPA conventions

The React application uses one `BrowserRouter` around the session, module registry, and administration shell. Register compiled pages through `NavigationRegistry` and render them under `AdminLayout` with `ProtectedRoute`. Use React Router `Link`, `NavLink`, `useNavigate`, or URL search parameters for internal navigation. Keep authorization checks in both the route guard and the Go API. An enabled module capability is not a user permission.

Settings uses `?tab=authentication` for its selected tab. Tab changes create browser-history entries without replacing the document or resetting scroll. The Authentication tab intentionally unmounts when left so an unsent client secret is discarded. Other page-local draft state remains mounted while the page is visible. Do not put secrets or authentication state in browser storage or route state. A route change may unmount the old page; preserve durable filters or pagination in the URL when users need to return to them.

Use `useQuery` for cached GET requests and `useMutation` for ordinary JSON writes. A successful write invalidates related query paths and the audit list. Existing rows remain visible while the affected query refreshes; unrelated query results stay cached. The mutation hook guards against simultaneous submissions and emits one global Snackbar success or error notification. Components should keep input values, selected IDs, and dialogs in React state and avoid page reloads after writes. For specialized authentication operations, retain their typed API client and explicit outcome handling; activation POSTs must never be retried automatically.

The cache is scoped to the authenticated issuer and subject and is disposed when that identity changes or signs out. A 401 expires the UI session; backend authentication and RBAC remain authoritative. Do not carry protected data between identities. OIDC sign-in is intentionally a browser navigation to `/api/auth/login`, and the provider's authorization URL intentionally opens outside the SPA. OIDC logout remains an API POST.

Vite serves deep links during development. Production hosting must serve `index.html` for application paths such as `/settings?tab=authentication`, while routing `/api/*` to Go and serving static assets normally. A production proxy must not rewrite API failures into HTML success responses. Browser Back/Forward should restore URL-based navigation state; background reads and writes should not call `window.location` or `window.scrollTo`.

Vitest/jsdom tests cover router history, component state, query refresh, mutation deduplication, and guards. jsdom cannot establish that a real browser never reloads a document or that production deep-link rewrites work. Verify those with a deployed-browser smoke test: open a protected nested URL directly, navigate through the sidebar and Back/Forward, edit a record while scrolled, check that the document and shell remain mounted, then test sign-in and sign-out separately.
